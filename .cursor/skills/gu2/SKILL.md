# GU2 —— 软件开发大综合 2

本 skill 服务 **SQA HND Computing: Software Development** 的项目型记分单元 **Graded Unit 2**，单元代码 **H48W 35**（2018-07，version 03，2 个 HN 学分，SCQF 8）。国内中心常把这一门叫做「大综合 2」。

它证明的是已经学过的技能：读懂任务、计划、用面向对象分析和设计、实现、测试、写文档、评估产品和自己的过程。它不要求展示一门新语言。

## 材料优先级

按这个顺序读，后面的材料不得覆盖前面的分数、模板、截止日期和禁则：

1. **中心材料**。考生目录常见为 `D:\SQA-SD\大综合2`，工作区里也可能叫 `大综合2`、`GU2`、`graded-unit-2`。先通读该目录里的每一个文件：任务书、评分表、封面、日志格式、字数、语言、图表编号、是否要求英文。
2. 本 skill 的 `references/evidence.md`（阶段证据与分数）和 `references/edu-system.md`（当前教务系统怎么对上交卷）。
3. 公开单元说明：<https://www.sqa.org.uk/files/hn/H48W35.pdf>。引用时写单元代码和版本，不要把说明书大段贴进报告。

编写本 skill 时，云端环境没有挂载 `D:\SQA-SD\大综合2`。清单来自 H48W 35 的证据要求，并用本仓库 `src/` 的实际行为做了对照。中心文件一旦放进工作区，先重读它们，再改证据结构。

## 何时使用

- 写或改 GU2 的计划报告、设计、实现说明、测试、用户文档、评估报告、日志。
- 把教务管理系统整理成可以对照评分点的证据。
- 检查三阶段是否都达到最低证据，以及用例、设计、代码、测试、评估是否互相指得上。

只画 UML、不谈交卷时，用 `drawio-uml-gen`，不必展开本 skill 的报告结构。

## 诚信与考生自己的证据

SQA 要求作品是考生本人的，中心会用过程见面和追问来核验。协助时遵守这些界线：

- 计划、设计决定、测试记录、日志、评估里的「我学到了什么」必须来自考生实际做过的事。没有运行过的测试写成「未执行」，不编造通过截图、会议记录或个人反思。
- 引用教材、网页、同学讨论要进参考文献。图和句子若不是考生写的，标注来源。
- 草稿标明 `DRAFT`。交卷前由考生通读，并改成自己的表述。
- 上一阶段的最低证据未齐，不开始写下一阶段的正式稿。补救（remediation）只补小遗漏，并在日志里记下改了什么。
- 重考必须换一个实质不同的项目。不要把本次作品改头换面当第二次提交。

## 分数

满分 100。三阶段都要单独达到该阶段满分的 50%，并且该阶段的最低证据全部齐，才能过这一阶段。

| 阶段 | 满分 | 本阶段及格线 | 证据形态 |
|---|---:|---:|---|
| 1 Planning 计划 | 40 | 20 | Action Plan 报告 |
| 2 Developing 开发 | 40 | 20 | 作品集：程序、测试、用户文档 |
| 3 Evaluating 评估 | 20 | 10 | 评估报告 |

总评：A = 70–100，B = 60–69，C = 50–59。A 档是一份前后呼应的作品：任务理解准确、内容紧扣任务书、结构清楚、技术语言稳定、技能是整合在一起的、过程基本自主。各小项分数见 `references/evidence.md`。

语言：任务书指定中文或英文时照办。任务书没写时，报告正文用英文（SQA 外部核验的常用语言），UML 图题用 `drawio-uml-gen` 的英文标题。

## 工作顺序

### 0. 锁定范围

读任务书和当前代码。用几句话写出：

- 系统名称、给谁用、解决什么问题。
- 本次交卷**包含**哪些用户目标，**明确不做**哪些（写进范围说明，评估时用来解释，而不是临时删用例）。
- 开发环境：本仓库是 React 18、TypeScript、Vite、Tailwind、Zustand、`localStorage`。架构叙述以 `src/` 为准，`.trae/documents/` 有过时描述（例如把状态管理写成 Context）。

本仓库的角色、路由和已知限制见 `references/edu-system.md`。写文档前再对一遍代码，代码变了就改文档。

### 1. 计划（先内容，后图）

Action Plan 至少覆盖下面三块，标题可以按中心模板改：

1. **任务分析（最高 14）**  
   用自己的话解释任务书。列出功能需求和非功能需求。给出顶层用例图。写背景调查（同类教务/成绩系统看过什么、借鉴了什么、没采用什么）。写项目目标。写资源（编辑器、浏览器、Node、本仓库、参考书）和信息来源。
2. **项目计划（最高 6）**  
   三阶段各自的时间、总完成日、里程碑、交付物、主要任务、资源。日期要能在剩余时间里做完；做不到的范围写进「不做」。
3. **分析与设计（最高 20）**  
   用 H172（面向对象分析与设计）的静态模型和动态模型，外加用例描述。设计必须对得上第 2 阶段真的会做出来的程序。

设计图一律走 `drawio-uml-gen`：

1. 先读该 skill，并读它的 `references/anti-patterns.md`。
2. 有两种写法的约定（活动图分支画法、用例数量、对象数量）先跟考生确认，再写 JSON。
3. 图题、CRC 单列、类图动词白名单、时序图参与者次序，按该 skill 的「范例风格基准」。
4. `python scripts/generate.py spec.json --check-only`，再生成，再 `preview.py`，再沿一条完整场景对五类图做交叉核对。
5. 不手改 `.drawio` 后拿旧 JSON 覆盖。

本项目建议的图，和「一个用例走通所有图」的主场景，见 `references/edu-system.md`。顶层用例图进计划报告；每条非平凡主流程配一张时序图和一张活动图。类图是静态模型，CRC/名词分析说明类从哪来。

需求编号用稳定 id（`FR-01`、`NFR-01`），后面的测试和评估引用同一个 id。

### 2. 开发

对照已接受的设计实现，并留下能给阅卷人看的证据。分数拆成：

| 证据 | 满分 | 怎么才算数 |
|---|---:|---|
| 问题域代码 | 5 | 成绩状态、权限、申诉流转、课表冲突这类规则落在可指出的函数或模块，而不是只散落在 JSX 里 |
| 界面代码 | 5 | 页面按角色可用，空输入、越权、失败提示看得到 |
| 自学的库或构造 | 5 | 课程外自己查来的库或语言构造，报告里写查了什么、为什么用、用在哪 |
| 错误处理 | 5 | 校验、拒绝非法状态、异常或等价的失败路径，而不是静默成功 |
| 内部文档 | 5 | 命名、缩进、模块注释和关键决定的说明前后一致 |
| 测试计划 | 5 | 从用例和需求 id 来的用例表：前置、步骤、数据、期望 |
| 测试执行 | 5 | 真的跑过。记下日期、结果、失败后的修改。没跑的标成未执行 |
| 用户文档 | 5 | 按真实界面写：谁能登录、做哪几件事、看到什么、出错怎么办 |

问题域和界面要在报告里分得开。当前 Zustand store 和页面混在一起时，评估里如实写这个弱点；若抽取纯函数，函数要有测试，并在设计里补上对应类或模块，保持计划与实现一致。

日志按周或按次记录：计划做什么、实际做什么、偏离、决定。这是过程分和真实性的主要证据。

### 3. 评估

评估报告五段都要有，每段指向具体证据（需求 id、文件路径、测试编号、日志日期）：

1. 任务概述，以及每个纳入范围的需求做到了哪一步。
2. 产物的优点和缺点（程序、设计、文档分开说）。
3. 以后做什么、为什么值得做。
4. 计划、设计、实现中途改了什么，意外事件怎么处理。
5. 这次新用上或练熟的知识技能，过程如果重来会改哪一步。

个人反思用考生自己的句子。代理可以列事实缺口（例如「测试 TR-04 没有执行记录」），由考生决定写进反思的原话。

职业伦理（H1F7）放在评估或计划的非功能需求里：成绩、身份证号是个人数据；角色权限；口令目前如何保存；浏览器端校验挡不住直接改本地数据。写成已做到的控制和未做到的控制，两边都写。

## 交叉核对

交卷前沿**一条主场景**走完，再抽一条失败路径：

- 用例图上的每个用户目标，都有需求句子、实现入口、至少一条测试、评估里的一句达成情况。
- 时序图上的每条消息，都是接收类上真实存在的操作（`drawio-uml-gen` 的校验器会查）。
- 活动图泳道是 actor 或类，不是一个叫 System 的泳道。
- 类图上的类，在名词分析里有去留理由。
- 代码里的角色矩阵与用例图的 actor 一致。`references/edu-system.md` 的矩阵以源码为准，过时就改矩阵，不改源码来迁就旧文档，除非考生正在做的就是那次修改。
- 评估里的每个优点缺点，都能在仓库或测试记录里指出来。

用技能自带的存在性检查扫一遍文件齐不齐（它不判断质量）。在本仓库里：

```bash
python .cursor/skills/gu2/scripts/check_portfolio.py <portfolio目录>
```

从用户技能目录运行时，把路径换成该目录下的 `scripts/check_portfolio.py`。

缺的槽位补文件或在报告里说明「中心模板用了另一个文件名」。脚本退出码 0 只表示文件在，不表示可以交卷。
