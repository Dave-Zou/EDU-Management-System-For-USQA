# H48W 35 证据细则

单元：**Computing: Software Development: Graded Unit 2**，代码 **H48W 35**，2018-07 version 03。这是项目型实用作业，不是闭卷考试。下面是公开单元说明里的证据结构，用交卷时能执行的话重写过。中心评分表如果把同一块拆成不同分值，以中心评分表为准。

官方文本：<https://www.sqa.org.uk/files/hn/H48W35.pdf>

## 项目必须长成什么样

任务要有说不清、需要先调查才能定下来的关系和约束。允许的题目包括：一个较大系统中的若干用例、给外部客户做的小型应用、考生自己提出并经考核员同意的面向用户的小型 Web 或移动应用。

考生要自己完成六件事：解释任务书、搜集信息把任务书说清楚、选定并做出设计、实现、评价产品与过程、评价自己的表现。

考核员是促进者。高分来自自主决定。过程见面要记在日志里：问了什么、考生怎么答、改了哪一版。

## 阶段 1 — 计划（40）

一份 Action Plan 报告，三块都要有。

### 任务分析（最多 14）

- 用自己的话解释任务书，指出含糊的地方以及考生如何把它定下来。
- 初始功能需求、非功能需求。
- 顶层用例图（actor 在系统外，用例是用户目标）。
- 为澄清任务书做的背景调查：同类问题、看过的产品或资料、哪些做法被采纳。
- 项目目标（做完后谁能完成什么）。
- 资源与材料，以及从哪获得。至少写开发环境。
- 信息来源清单，正文里引用过的都要能在这里找到。

### 项目计划（最多 6）

正式计划，时间要现实：

- 每个阶段的日程和总完成日
- 里程碑和交付物
- 主要任务
- 资源

### 解决方案：分析与设计（最多 20）

- 用合适的技术做分析。对本专业，默认是名词分析、CRC、用例描述。
- 给出原型应用的分析与设计证据。对本专业，默认是类图（静态模型）加上时序图和活动图（动态模型），对应已经完成或正在完成的 H172。

设计里出现的类、操作、状态，要能在第 2 阶段的代码里找到，或在评估里说明为何改掉了。

计划阶段最低证据缺任何一块，这一阶段不算过，不能把开发阶段写成正式提交。

## 阶段 2 — 开发（40）

作品集。截图、代码路径、日志、报告都可以，但每一分都要指到具体产物。

### 应用程序（最多 25）

| 项 | 分 | 阅卷人要看到的 |
|---|---:|---|
| 问题域 | 5 | 领域规则有实现：对象、状态、校验、集合的使用（呼应 H171、H16Y） |
| 界面域 | 5 | 用户完成用例的界面，含反馈 |
| 不熟悉的库或构造 | 5 | 考生自己查资料后用上的库、API 或语言构造；写明出处和学习过程 |
| 错误处理 | 5 | 异常、输入校验、非法状态被拒绝并留下痕迹 |
| 内部文档 | 5 | 命名习惯、缩进、对非显而易见决定的注释 |

### 测试（最多 10）

| 项 | 分 | 阅卷人要看到的 |
|---|---:|---|
| 测试计划 | 5 | 测试用例，必要时含测试用具。从需求和用例来，而不是从「我记得测过登录」来 |
| 测试执行 | 5 | 运行记录、实际结果、和期望的差异、随后改了什么 |

没跑的用例保持「未执行」。不要把计划抄进执行栏再填 Pass。

### 文档（最多 5）

用户文档：按真实界面写操作步骤，可以附带界面内的帮助文字。读者是会用该角色账号的人，不是读代码的人。

## 阶段 3 — 评估（20）

一份报告，评价整个做法是否有效。五段都要出现：

1. 任务概述，以及方案在多大程度上满足任务书里的原始需求。逐条用需求 id。
2. 实用作业**产物**的优点和缺点。产物包括程序、设计和文档，不要只评价「我很努力」。
3. 以后可以怎么发展这个方案，并说明理由。
4. 项目期间对计划、设计或实现做过的修改；预料之外的事件；当时怎么处理。
5. 做项目时获得或加深的知识技能；如果重来，行动或过程会改哪里。

## 等级标尺

同时满足「每阶段 ≥ 50%」和「每阶段最低证据齐全」之后，才按总分定级：

| 等级 | 总分 |
|---|---|
| A | 70–100 |
| B | 60–69 |
| C | 50–59 |

A 与 C 的差别在作品是否连贯、任务理解是否准确、是否紧扣任务、语言是否稳定、技能是否整合成一件事、过程是否自主。补救和重评之后，按完成时的证据给分，取考生得到过的最高等级。

## 建议写进设计的已修单元

任务书通常会抽样下列成果。写设计时点名用到了哪一条，避免报告变成与课程无关的产品说明。

| 单元 | 在 GU2 里怎么体现 |
|---|---|
| H173 34 Developing Software: Introduction | 能跑的实现、按习惯写的技术文档 |
| H1F7 34 Professionalism and Ethics | 行为准则、成绩等个人数据、访问控制的伦理讨论 |
| H177 34 Troubleshooting | 一个真实缺陷：调查、处理、记录、回顾 |
| H171 35 Object Oriented Programming | 设计被实现成对象，而不是只有界面 |
| H172 35 Object Oriented Analysis and Design | 用例、静态模型、动态模型 |
| H16Y 35 Data Structures | 明确选用的集合或抽象数据类型，并说明为什么 |
| H17D 34 Project Management（修过则写） | 计划、里程碑、进度与日志的对照 |
