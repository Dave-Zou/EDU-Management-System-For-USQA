## 已经能当作今年要求来用的

这些在转写里说得比较死，而且和 H48W 35 不冲突。

**合成一个文档。** 范老师今年要求把书面证据做进一个文档。有人交了二十多个文件的压缩包，被看成没按要求写。这不是「少交一整部分」那种 RT，也不是被写成作弊。下一届格式可能再变，所以不要把「一个文档」写成永久规定；在读到今年通知之前，按一个文档准备。学生猜测「只要 Word、不要源文件」不能用：单元规范的作品集包含实现，代码要能被抽查。一个文档指的是报告，不是把程序丢掉。

**四个子系统，或者三个加上会议纪要。** 评分会看用例是否落在项目简报的四个子系统上。只做一个，结构不够。范老师允许因进度改做三个，但会议纪要里必须写明：主席认为以当前进度做不完四个，所以主开发是哪三个，以后还可以怎么调整。不写这句，就按四个做。

转写里出现过的功能碎片，**不是**四个子系统的正式名单：成绩登记、assessment 或 exam details（有人被建议可以不做其中一块）、班级管理。正式名字以项目简报为准。

**会议纪要后面写语言。** 选用哪种语言、为什么，写在会议纪要之后。辅导里说过可以只写 C#，不必把整套技术栈都展开。「最简单就是 C#」是考生自己的理解，不是课件原文。

**隐含要求和数据实体。** 模板或辅导要求这一节：student 收集什么，班级和课程收集什么，管理员收集什么。

**Stage 2 的数据访问。** 2026-10-19 的 PHP 课上，老师说 stage 2 要用 ORM：用类把对象存进数据库，而不是在界面里手写 SQL；不用会丢不少分。C# 和 Java 都要知道各自怎么做。同一段转写另有一句「用 C# 就去看 internet 服务，用 Java 就去看 ORM」，两句不完全一致。课件打开后以课件为准。在此之前，计划里必须写清数据库访问方式。没有数据库，就要在评价里把这一项写成未满足，不要写成已经用了 ORM。

**阶段反馈用中心的等级字母。** 范老师在第一部分不报 A/B/C，只说 S、RD、RA、RT。考生重听第一节课并对照 PPT 后的转述是：RT 只有作弊、缺席、少一个部分。官方 70/60/50 的 A/B/C 仍以 H48W 35 为准，不要把连连看那门课的 60 分制搬过来。等级 C 的描述里有「项目期间接受额外支持并返工」：RD 之后按老师意见改过，评价的修改节要写改了什么。

**页数不是过关线。** 转写里出现过三十多页到八十页。东西齐就可以，缺一整块不行。

## 版式：课件没读之前不要自拟

范老师用过一节课讲格式。考生估计格式占分很重，这只是估计，不是分数表。

- 封面按模板：只有文字、全部居中、字号一致。范老师口头说过封面不是重点。版式照模板，不要在封面上堆内容。
- 纸张、页边距、一行字数、文档方向以那节课的课件为准。异常纸张和页边距会被看成不是按课件排的。
- 第一次课课件规定代码以什么格式放进文档。具体字体和行距未读到，不要编。
- 信息来源那一节要指向文末文献表。链接放在文末，不放在第一节开头。老师给的标题不要改措辞。
- 表格跨页要不要重复表头，课件没说就不要自己加。

## 计划和范围

- 计划阶段的任务列表里不要夹开发任务。
- 开发阶段的任务名用课件里范老师写的前几项。考生曾把「确定最终设计」放进开发阶段，认为应该删掉。条目本身以课件为准。
- 「每个阶段留 1 到 2 天机动」在转写里出现过，说话人不可靠。对照第一节课件再决定写不写。
- 页面设计可以手画。不要用 HTML 充当设计图。有人把界面收成七个页面，这不是标准。
